The Fail-Direction Rule

Which way to round a value feature when you are not sure — and why the answer is opposite for “my capability” and “their threat”.
Your one win today Look at any uncertain number that feeds a decision and decide, from first principles, whether to round it up or down — by naming which mistake is catastrophic. This is the whole design spine of the oracle in #137.

1The blunder that named the rule

Pokémon example — the f70 false famine

Our Active Dragapult ex has 0 Energy attached. Our hand holds Crispin. The agent’s stall equation read the board as “0 Energy → can’t attack” and chose a defensive stall worth about +105.

It was wrong. Crispin (verified at source, SCR 133) “Search your deck for up to 2 Basic Energy cards of different types … put 1 into your hand. Attach the other to 1 of your Pokémon.” So Crispin attaches one Energy itself and hands us a second of a different type — which our still-unused manual attach then plays. Dragapult ex reaches RP this turn → Phantom Dive 200 + 6 counters. The agent threw away a winning turn.

The AI was not missing the cards — they were sitting in its hand. It was missing a number: how much Energy it could still attach this turn. And that number was being rounded the wrong way. Issue #137 exists to compute that number correctly. Today’s lesson is the principle it is built on.

2The idea: uncertainty forces a rounding choice

A value feature is a number the agent computes about a position to help it choose (you met these as φ, the features, in the textbook). Most features are estimates — we do not model the whole world. reachable_attack asks “can my body pay for an attack this turn, counting everything I could attach?” We cannot always be certain (a card effect we haven’t modelled, an Energy that might still be buried in the deck). Whenever an estimate is uncertain, you must pick a direction to round it.

The rule for picking the direction is not “round down” and not “round to the nearest truth”. It is:

The fail-direction rule

Round toward the mistake you can afford. Away from the one that is catastrophic. Name the two possible errors — a false “yes” and a false “no” — decide which one loses you a game, and make the estimate structurally unable to commit that one.

Two names for the two directions:

  • Fail-closed — when unsure, answer the safe, conservative way; refuse to claim more than you can prove. reachable_attack is fail-closed: an Energy source we can’t verify contributes zero to the budget.
  • Fail-open — when unsure, answer the alarming way; assume the worst is real. Its twin oracle reachable_incoming (how hard the opponent can hit us next turn) is fail-open: an unproven threat is credited.
Toolbox — you already ship this embedded

This is fail-safe design, your home turf. A watchdog timer that isn’t sure the CPU is alive resets — it doesn’t assume “probably fine”. A brake controller that can’t trust a wheel sensor commands the safe state. You never round a safety-critical reading toward convenience. A value feature is the same discipline: round toward the error you survive.

3Why the direction flips: same principle, opposite rounding

Here is the part that trips people up. The two oracles round in opposite numeric directions — one under-counts, one over-counts — yet they obey the same principle. The principle is “always be pessimistic about your own safety.” Which number that makes you round down vs up depends only on whose capability the number measures.

Read the two “catastrophic false” cells together: both are a false sense of safety. To kill a false sense of safety you shrink your own reach and inflate theirs. Opposite arithmetic, one goal. The #137 handoff says it in one line: “the OPPOSITE fail direction — here under-count the budget, there over-count the threat.”

The road not taken — why not just fix the stall?

The tempting patch: add a special case to the stall equation — “don’t stall if Crispin is in hand.” That is a gate at the wrong altitude. The same missing number mis-prices promote, retreat, and doom too. The ruling was to fix it once, at value altitude: build the honest budget primitive and let every decider read it. One correct number beats five special cases — the same instinct as replacing scattered magic constants with one calibrated table.

4Worked problem — compute the budget by hand

Let’s run reachable_attack on the f70 board the way the code will. Costs verified at source (EN_Card_Data.csv): Jet Headbutt = C (one colourless, pays with any Energy), Phantom Dive = RP (one Fire and one Psychic — typed slots, only that type pays).

# State: Active Dragapult ex, attached = {}  (0 Energy)
# Flags: energy_attached = False   supporter_played = False
# Hand:  Crispin (Supporter, tutor_energy), + non-Energy cards

attach_budget(me, flags, hand):
    budget = []
    manual attach  (energy_attached is False)  -> +1 # one WILD (any type)
    Crispin playable? supporter_played is False -> YES
        Crispin FULL modelled yield:
            +1 typed straight onto a Pokémon         # choose {R}
            +1 typed of a DIFFERENT type into hand    # {P}, played by the manual attach
    => budget = { R (Crispin direct), P (into hand -> manual attach) }

reachable_attack(Dragapult, "Phantom Dive" = {R}{P}, budget):
    attached {} + budget {R,P}   greedy typed match:
        slot R  <- R  ✓
        slot P  <- P  ✓
    => PAYABLE = True   (Phantom Dive 200 is ON the table this turn)

reachable_attack(Dragapult, "cheapest" = Jet Headbutt {C}, budget):
    colourless slot {C} takes ANY energy -> R pays it
    => PAYABLE = True   ==>  famine = NOT payable = False   (NO stall)

Now the same board through the old approximation that shipped the bug — _active_attack_payable_via_accel:

# The bug: one accel card, +1 attach, cheapest cost only, UNTYPED
payable_via_accel = ( len(attached) + 1 ) >= minAttackCost
                  = (     0        + 1 ) >= 1            = True  # cheapest only
# It can prove the 1-cost slot, but it is blind to the 2-cost {R}{P} reach,
# and the stall gate keyed off a *different* premise ("0 attached") -> false famine -> +105 stall.

The fix is not a smarter +1. It is the full budget (both attaches), typed (R pays R, not “any 2 energy pay {R}{P}”), and fail-closed (a card whose effect we can’t read contributes 0). Those three properties are the lesson.

5Check yourself recall

Answer from memory — first pick locks. Effortful retrieval is what makes this stick.

1. A feature estimates what my own body can do this turn, and the estimate is uncertain. Round it…

Right — fail-closed. A false “I can attack” is the catastrophic error, so shrink your own claim.

The catastrophic error is a false “I can attack”. Round down so you can never commit it.

2. A feature estimates what the opponent can hit me for next turn, and it is uncertain. Round it…

Right — fail-open. A false “I’m safe” loses the game, so inflate their reach.

Here the catastrophic error is a false “I’m safe”. Round up to stay pessimistic about your survival.

3. Both oracles round in opposite numeric directions. What single principle sets both?

Exactly. Pessimism about your safety = shrink your reach AND inflate theirs.

It’s pessimism about your own safety — which means under-count your reach and over-count theirs.

4. For “can my body attack this turn?”, the catastrophic error is a false…

Yes. A false “can attack” switches off live safety deciders — that’s the game-loser.

A false “no” is merely a missed opportunity here; a false “yes” switches off a stall — that’s catastrophic.

6Spaced callback — from boolean to probability

Issue #137 also asks for readiness_p: instead of a yes/no, a probability that the budget lands. When the enabling Energy is certain (in hand, or guaranteed in the deck) it is 1.0. But when the enabler is still buried in the deck, we need the chance of drawing/fetching it — a distribution you already met in the textbook.

The hypergeometric distribution — sampling without replacement from the deck (deck_odds.draw_hit_probability, textbook Ch 6). Fail-closed still rules the boolean version: if you can’t bound the odds, credit 0. Notice the transfer — readiness_p is where today’s hard rounding rule softens into an expected value, which is exactly the bridge from Ch 6 (probability) to the value model.

7Where this transfers toolbox

  • Admissible heuristics (A* search, textbook Ch on search). A* stays optimal only if its cost-to-go estimate never over-estimates — a one-directional rounding rule chosen so the algorithm can’t make its fatal mistake. Same shape as fail-closed, different fatal error.
  • Sound vs complete static analysis (your world). A sound analyser rounds toward reporting bugs — it may cry wolf, but it never misses a real defect. Which false you tolerate defines the tool.
  • Type I vs Type II error / precision–recall. The same asymmetry in statistics: you pick a decision threshold by the relative cost of a false positive vs a false negative — never by “nearest the truth”.
