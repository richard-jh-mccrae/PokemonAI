## Authored this round

**Root-cause unblock — the Pilot can now *see* a search.** A search/fetch decision (`SelectContext.TO_HAND`)
offers `CARD` options that point into a **hidden** zone: a `DECK` candidate's id is revealed in the
select's own `deck` list, a `DISCARD` candidate's in the player's discard pile. `_option_pokemon` knew
neither (it only mapped hand/active/bench and never saw `select`), so **every fetch resolved
`card_id=None`** — no roles/tags/stat, so no rule could reason about *which card to take*. Fixed in
`pilot.py`: resolution is now `select`-aware (DECK → `select["deck"][i]`, DISCARD → `player.discard[i]`).
This unblocked the entire search cluster (3 corrections).

**Containment — board-intent rules gated to board actions.** Surfacing card roles/tags at `TO_HAND`
made the *board-commit* intent rules (`accel-into-main`, `tutor-the-wincon`, `dig-before-commit`,
`use-acceleration`, `dont-bench-multiprize`) **leak** onto fetch options (they only checked
`plan`/`roles`/`tags`). Each is now gated to its board-commit `option_type` (PLAY / ATTACH / EVOLVE) —
conceptually correct (they govern *playing/attaching*, not *which card a search pulls*) and it leaves
all MAIN-menu behaviour unchanged (the 24/30 held exactly).

**New card-function tag — `bench_fill`** on Buddy-Buddy Poffin (`function_overrides.json` + shipped
`card_functions.json`): fetches Basics straight onto the Bench (fast development + deck-thinning).

## Adversarial review (5 skeptics, one per rule — each tried to construct a misfiring board state)

Every rule was probed by an independent agent with a runnable harness. **3 fixes applied, 2 documented
as known limitations** (the proposed fix would have regressed a real correction). Corpus stayed 29/34;
suite 392 passed (+4 regression tests for the fixes).

- **fetch-the-wincon** — *fixed.* It fired off Roles alone with no board awareness: it beat
  `fetch-energy-when-starved` even when energy-starved (pulling a wincon you can't power), and pulled a
  redundant 2nd copy when the payoff was already in play. → Added an **energy-starvation guard** and a
  new **`Board.wincon_in_play`** flag (a Line payoff / win_condition Role already on Active or Bench).
- **dont-bench-multiprize** — *fixed.* My PLAY-only gate (added to stop the ToHand leak) was too narrow:
  **evolving** a Basic into a non-wincon ex also benches a multiprizer. → Widened the gate to
  `option_type in (PLAY, EVOLVE)` (EVOLVE is never a search sub-option, so no leak reopens).
- **prefer-bench-fill-first** — *fixed.* Fired even on a **full Bench** (Poffin places nothing) over a
  live draw. → Added a bench-room guard (`my_bench < _BENCH_MAX`).
- **fetch-energy-when-starved** — *documented, not changed.* The skeptic's `my_bench > 0` guard (fetch a
  body before energy when the Bench is empty) would **regress f93** — a real human correction that
  fetches Basic Energy with an empty Bench at turn 11. Per-option scoring can't see "is a body also
  fetchable," so a clean guard isn't expressible; the human correction wins. **Known tension** (empty-bench
  risk vs immediate energy need) for the ladder / human to adjudicate.
- **dont-chip-with-a-doomed-active** — *documented, not changed.* The skeptic's headline ("forgoes ~88
  free damage") is **mitigated by turn continuation**: attaching/developing does *not* end the turn, so
  after developing the agent still chips on the next sub-decision (−40 keeps any chip ≥ ~40 above the
  pass floor). The −40/ceiling-100 is the sweet spot for the corpus case (f47: chip 49.9 → 9.9, below a
  +15 attach but still > 0); lowering to −20 regresses f47. **Minor residual edge:** a tiny chip
  (tactical < ~40) with *no* development available is dropped (forgoes minor free damage from an
  already-doomed Active). Left as a documented limitation; the ladder A/B is the judge.
