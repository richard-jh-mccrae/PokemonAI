## Authored this round — the "develop-first" rebuild (build `mega_starmie_20260627_93a70be`)

**The reframe.** Most of this build's corrections looked like "forgo a KO / big hit to develop."
They are not. **An attack ends the turn, but the knockout it scores survives any action that
doesn't change the Active attacker** (attach, evolve a benched Pokémon, play a Trainer, fill the
Bench). The engine re-presents the open menu after each non-ending action, so a turn is many
`decide()` calls. The agent's pure-argmax was taking the KO (`tac≈1000`) on the *first* menu and
ending the turn before any development. The fix is **sequencing, not weights**. See
[[attack-is-turn-ender-develop-first]] in memory; this refines (does not overturn)
[[forgo-ko-corrections-are-refuted]] — a positional *weight* still must never drop a KO.

**Headline result (real Pilot over the corpus, the authoritative measure — not the additive
tuner):** 21 → **37 / 76** decisions now match the human's choice, **+16, zero regressions**.
On this build alone, **all 40** corrections no longer end the turn early (every remaining
"miss" is the agent doing a *different* development action, never an attack).

### Keystone — `_finish_turn_last` (pilot.py), "attack last"
At a single-pick MAIN menu offering an attack, beneficial **safe** development (a Hypothesis
scored it > 0; not terminal/Retreat; not an Evolve-of-the-Active when a KO is on the menu) is
sequenced ahead of the turn-ending attack; the KO falls to last and is taken the same turn.
- Fixes the "attack-too-early" family: ep82226759 f16/f29, ep82226116 f70, ep82224509 f29 (evolve
  the wincon first, then KO), and more. `chosen Attack → develop`, `fixed=True` for each.
- Adversarially reviewed (`attack-last-adversarial-review`, 5 diverse skeptics → verify →
  synthesize): **0 confirmed game-losing findings**; the KO is only reordered, never dropped.
  Applied its one cheap fix (#2): gate the reorder to `select_context == MAIN`.

(e.g. this run still proposes f31 and f19, both verified fixed). **The real `decide()` / the

not Cinderace) and **f9** (fetch Staryu, not Cinderace) are genuine next-round work. See
`docs/tuning/methodology.md`.

### Review refinement — promote is a 3-way priority (not "always the line piece")
Human review caught that `prefer-wincon-line-piece` over-promoted: at a PROMOTE (Active KO'd) it brought
up a bare Staryu unconditionally. Promoting a fragile pre-evolution with no way to evolve it just feeds
the opponent a free knockout. Corrected to the real doctrine (verified by unit test + the f94 corpus
case, 0 regressions):
1. **`promote-the-ready-wincon` (w40)** — a benched win-condition already powered to attack → promote it.
2. **`prefer-wincon-line-piece` (w18, promote branch now gated to `wincon_in_hand`)** — promote a
   pre-evolution only when the payoff is in hand to evolve it THIS turn (f94: Mega + energy in hand).
3. **`promote-the-staller` (w20)** — otherwise promote a disposable opener (`opener` tag, Cinderace):
   it stalls, keeps the Staryu safe on the Bench, retreats for free once you draw the evolution, and
   attacks if you find Energy. New signal `Context.card_is_wincon`.

### Cleanup — removed two rules attack-last made obsolete
Reconciliation against the real `decide()` (the additive tuner over-reports) found `build-before-attack`
and `dont-chip-with-a-doomed-active` are now redundant *and* harmful: attack-last already sequences
development ahead of the turn-ending attack, so the chip penalty's only remaining effect was dragging a
useful chip **below End** when no development was available — the agent did nothing instead of chipping.
Removed both (and the `_CHIP_CEILING` floor). Experiment: **+2** (81904451-17, 81905063-16, both
"attack when able"), **0 regressions**. Real-Pilot corpus now **42 / 57** active correct. Tests for the
removed rules replaced with `test_a_weak_chip_is_taken_when_no_development_is_available` +
`test_development_still_beats_a_weak_chip_via_attack_last`. Docs updated (general-strategy.md, weights.md).

### Generalized the sequencer to tiers (fixes f11)
`_finish_turn_last` now sequences the turn's commits in tiers, not just "attack last": **tier 0**
informative development (draw/search, bench-fill, evolve-bench, play) → **tier 1** the Energy attach
(the one irreversible per-turn commit) → **tier 2** the turn-ending attack (+ Retreat/End). Same
rationale as attack-last, one level down: dig first (free, reveals a better target), commit the attach
after. Fixes **f11** (ep82225643 — play Pokégear before attaching Ignition; `accel-into-main` no longer
front-runs the dig). Runs at any single-pick MAIN menu (f11 has no attack option). Real-Pilot corpus
**43 / 57**, 0 regressions, 422 tests. The KO guard is unchanged (Evolve-of-Active → tier 2 when a KO
is present). The vestigial `attach-energy-last` (−5) nudge is now subsumed by tier 1 but left in place.
